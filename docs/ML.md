# REVORA ML — Recovery Probability Model

## What the model predicts

`P(customer pays | failure cause, chosen action, case context)` — the probability
that a specific recovery action on a specific at-risk payment results in recovery.

## Provider chain (in `app/intelligence/recovery_score/`)

```
decide() ──► estimate(cause, action, stats, features)
                │
                ├─ 1. trained artifact (models/recovery_model.joblib)
                │     served only if: feature_version matches AND action seen in training
                ├─ 2. empirical base rates (≥30 real outcomes for cause×action,
                │     control-arm cases excluded)
                └─ 3. cold-start prior 0.30 (explicitly labeled, low confidence)
```

Every decision row records which basis produced the chosen estimate
(`model:xgb_cal_v1` / `empirical(n=…, k=…)` / `cold_start_prior`). No estimate is
ever presented under a false basis.

## Features (v1 — frozen order, 28 dims)

log_amount, attempt_number, retry_count, contact_count, is_vip,
prior_payment_count, prior_failed_count, hour_of_day, day_of_month,
method one-hot (4), cause one-hot (8), action one-hot (7).

Built domain-side (`domain/recovery/case_features.py`) from real DB rows;
vectorized intelligence-side (`intelligence/recovery_score/features.py`). Stale
artifacts (feature_version mismatch) refuse to serve — automatic fallback.

## Training data — the synthetic corpus (declared simulation)

Generated by `python -m app.infrastructure.scripts.generate_corpus --n 6000 --seed 42`:

- **Real pipeline:** ingestion → rules classifier → risk detection → case creation →
  state machine → outcome recording all run through production domain code.
- **Randomized action assignment** (uniform over permissible actions) — exploration-style
  coverage, mirroring the experimentation engine.
- **The world's response is simulated** by a documented DGP with known ground truth:
  cause×action effectiveness (e.g. expired-card+retry ≈ 0.02 vs update-method ≈ 0.65),
  payday-window retry boost (+0.20), VIP responsiveness (+0.10), retry fatigue (−0.15).
- Every row is `is_synthetic=true`; every outcome `source="simulator"`;
  every execution `result.simulated=true`. Never presented as live merchant data.

The DGP's value: held-out metrics measure whether the pipeline **recovers known
ground truth** — an honest evaluation, not a claim about real-world data.

## Held-out evaluation (20% stratified split, n_test=1200, seed 42)

*(Retrained during the 2026-08-26 stabilization audit after the serving-gate fix
— the actions list is now recorded in the artifact metadata. Same corpus DGP,
seed, and hyperparameters; numbers below are the retrained artifact's real,
recomputed values.)*

| metric | logistic baseline | XGBoost calibrated (served) |
|---|---|---|
| AUC | 0.6886 | **0.6907** |
| Brier | 0.2124 | **0.2120** |
| Log loss | 0.6102 | **0.6091** |
| Precision @0.5 | 0.5530 | 0.5537 |
| Recall @0.5 | 0.3654 | 0.3611 |

Honest findings, reported as-is:
1. On this DGP the calibrated XGBoost is **at parity** with logistic regression —
   the DGP is near-linear in its features. We serve the XGBoost (captures
   interactions as real data grows) and ship the baseline comparison as evidence
   we measured rather than assumed.
2. The decision layer's value does **not** depend on model superiority: expected-value
   selection, the policy gate, bounded execution, and incremental measurement do the
   heavy lifting; the model only needs calibrated-ish rankings.
3. Recall@0.5 is low because 0.5 sits above the 38% base rate — nothing operationalizes
   a raw 0.5 threshold; expected value makes the trade-off.

Reproduce: `evaluation_report.json` + `models/recovery_model.joblib` (committed
as submission evidence; regenerate with the two CLI commands above).

## Guardrails

- Model can only **recommend**; the deterministic policy gate can block anything.
- Unseen actions are never extrapolated (fallback to empirical/prior).
- `no_action` EV ≡ 0 by definition — organic recovery is never claimed as recovery
  caused by the system (incremental attribution is the experiments engine's job).
